01 — The problem

Paid per booked appointment, running on six disconnected tools.

The agency ran paid media for roughly a hundred U.S. home-service contractors — roofing, flooring, painting, remodeling, HVAC, solar — and was paid mostly per booked appointment, not per lead. That billing model is the whole reason the system exists: a cheap lead with an empty calendar is still a failure, so every number had to survive the trip from ad click to confirmed appointment and back to an invoice.

What existed instead was six disconnected systems. The client roster in ClickUp, the CRM in GoHighLevel with one sub-account per client, dials in a dialer, spend in Meta and Google Ads, appointments in a spreadsheet, and the books across eight banks and gateways in two currencies. Four internal teams each kept a private spreadsheet that disagreed with the other three, and “is client #437 profitable this month” was a day of manual work.

02 — Architecture

Three rules, and every incident came from breaking one.

The database is the source of truth — not the SaaS tools, not the front end.

Churn, attribution freezing and lifecycle transitions are triggers and RPCs in Postgres. Four teams read the same numbers and each had an incentive to define them favourably; a definition that lives in a view gives the same answer in the console, in a workflow, in the query agent and in a reconciliation script.

No external system writes to a table directly.

Everything goes through SECURITY DEFINER functions. Row-level security blocks anonymous writes outright and the anon key is public by design — it ships in the browser bundle. The practical win: the contract nine workflows depend on is a function signature, not a table shape.

The front end decides what to show; the database decides what is allowed.

Every sensitive action is re-checked inside the RPC. Page-level access control is a UI convenience — the code says so explicitly, because the next person to read it will assume otherwise. The real boundary is RLS.

03 — Case studies

Nine systems, and what was actually hard about each.

01

The platform

Postgres as source of truth, ten-role RLS, and a two-way sync with a spreadsheet-shaped SaaS that stayed the system of record.

Field-ID mapping that survived a rename · upserts that never blank a field · per-field locks so humans beat robots
02

AI call auditing

Every recorded sales call transcribed and scored against a weighted rubric, surfaced to the manager who has to coach the setter.

The model judges, code counts · calibration rules written from real disagreements with the sales manager
03

Finance pipeline

Eight banks and gateways, two currencies, one append-only journal, accrual periods separate from cash dates.

Found the baseline spreadsheet's own rounding corruption · FX taken from the processor, not the central bank
04

Paid-media pipeline

Ad-level Meta, Google Ads and Local Services spend, daily, per client, joined to the appointments that got booked.

A rolling window instead of a cursor, because platforms restate · a metric that is intentionally double-counted, and why
05

Campaign creation engine

A form that turns a Drive folder of creative into a built, paused Meta campaign — resumable halfway through.

Idempotency at three levels · retryable vs terminal failure as a product decision, not error handling
06

Conversion tracking

Server-side Conversions API keyed on booked appointment — the latest-stage event that still lands inside the attribution window.

One reusable workflow for every client · onboarding reduced to a database row and a webhook
07

CLAUD.IA

Ask the database a question in plain language, over registered datasets, on a small model.

The catalog goes in the prompt, not behind a tool call · a filtered zero is not “there are none”
08

Infrastructure resilience

A stateful engine that would not reconnect, on a network that flapped up to sixty times a day.

Recovery in ~3 min, zero inbound webhooks lost · two sync workflows held 76% of all stored execution data
09

Cap Ruche video editor

A browser 9:16 editor for ad creative: 30 s of 1080×1920 exported in 4.7 s on a laptop GPU.

Integer-microsecond edit core · the audio clock is the clock · an E2E test that parses the exported MP4
04 — Lessons

Almost nothing failed loudly.

The dangerous failures in this system returned HTTP 200, logged success, and produced a number that was plausible and wrong — and a plausible wrong number survives review, gets presented to a client, and becomes the basis of a decision. Most of the engineering effort went into making failure visible.

A sample of what is written up in full: PostgREST truncating silently at 1,000 rows, and the four unrelated-looking incidents it caused. A dedup query that hit that ceiling and regenerated the same 65 records every five minutes — $6.77 a day, logging success. A view without security_invoker ignoring row-level security entirely. A dunning ladder that ran at 08:00 Eastern, found every Eastern client outside the permitted contact window, and silently never retried. Date-only imports stored at midnight UTC that moved ten appointments from June into May. A pagination option misspelled in a way that made a sync process 100 of 319 clients with no error anywhere. An index 16× larger than the data it indexed.

And the ones that are not about code: a migration repository that was an honest log of intent and a useless description of state; a system with no tenant_id that was right to not have one and should have written that down as a decision; and secrets that ended up in three habitats because each shortcut was defensible in a different week.

05 — Stack

What it was built with.

Automation

Front end

React, TypeScript, Vite, TanStack Router and Query, Tailwind v4, shadcn/ui, Recharts

AI

OpenAI with strict function calling, Anthropic Claude, Deepgram nova-3 speech-to-text, Whisper word-level timestamps

Integrations

ClickUp, GoHighLevel, HotProspector, Meta Marketing & Conversions APIs, Google Ads (GAQL), Google Local Services, Stripe, Asaas, Plaid, Make, Fathom, WhatsApp

Media

Meta Ads, Google Ads, Google Local Service Ads, server-side conversion tracking, creative production tooling

06 — Role

A two-person engineering team.

Lucas Zuque — architecture and data modelling; the Postgres layer (schema, RLS, RPCs, triggers, views, migrations); the AI layer (audit rubric and calibration, booking-message generation, objection classification, CLAUD.IA); the finance pipeline end to end; paid-media ingestion and the campaign creation engine; infrastructure resilience; and the engineering documentation that let anyone else work on the system.

Letícia R. — platform engineering, the console, and much of the ClickUp and GoHighLevel integration surface.

Media buying, customer success and call-centre work was done by the agency's operating teams; the OS is what they ran on. The audit rubric and the daily-report tiers were calibrated against the sales manager's own judgment rather than invented in isolation.
